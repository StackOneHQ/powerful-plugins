# Hard and soft constraints

Hard constraints go into the brief word for word. Soft constraints stay out, because each one
anchors the build to a known shape. When an item could go either way, ask whether breaking it
would make the asset wrong (hard) or just different (soft).

| Asset | Hard: keep | Soft: leave out |
|---|---|---|
| Presentation | Facts, figures, quotes, names; slide count if a talk slot fixes it; aspect ratio; must run offline | Slide templates, title-bullets-image layouts, section order, "one idea per slide", example decks |
| Launch or demo video | Real product names and on-screen strings; claims that passed review; aspect ratios and maximum length set by the platform; captions for sound-off viewing | Story templates, beat timings, scene lists, archetypes, reference films, target length below the platform maximum |
| Product mockup | Real labels, fields and states of the product; data that is fictional but plausible; no personal data | Grid, framing, device chrome, house mockup kit, camera angle |
| Web page | Required copy, links, legal text, accessibility (contrast, reduced motion, keyboard use) | Section templates, hero patterns, component library, example pages |
| Document or report | Facts and sources, required sections a reader depends on, word limit if one is set | House outline, heading scheme, tone guide beyond banned phrases |

Brand marks (a logo, a product name written a certain way) are hard only when the user requires
them. Brand colour and type are soft unless the user says otherwise; when the asset must stay on
brand, list the exact colours and fonts as hard.
