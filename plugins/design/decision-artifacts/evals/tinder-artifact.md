# Tinder Artifact checks

In a marketplace checkout, run `node --test tests/tinder-*.test.mjs` from the repository root. It uses a temporary recording CLI and a loopback receiver to test calls to the issuing chat, draft scope, and repeat delivery.

For a browser check, render the bundled After Hours example with the documented renderer command. Confirm the first option is already selected. Approve with a right swipe, add context with an upward swipe, and dismiss with a left swipe. Open dismissal feedback and wait past three seconds before saving. Change the device mix on the next screen. Review the batch and check that saved feedback remains on its original decision. Download the PNG and brief and verify that they reflect the reviewed choices. The blank challenge should open without the prior reviewer's answers.

Test a paired batch on the actual host before claiming automatic follow-up. A queue receipt establishes that the host accepted the batch. A reply in the originating chat establishes delivery and follow-up.

## Exercise each job

- Guide a task. Ask for a launch brief with a choice of audience and a dependent tone decision. Change the audience after approving the tone. The tone must ask for review again.
- Review prepared work. Request two versions of a heading, approve the second, then undo and request different wording. Submit again and check that the original frozen text and revision remain identifiable.
- Triage items. Shortlist one optional idea and dismiss another with a note. In the final packet, only the shortlisted idea may request work. Repeat with all ideas dismissed and check that feedback can still return to the chat.
